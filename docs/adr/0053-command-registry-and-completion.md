# 53. One command registry drives help and completion in every client

Date: 2026-10-11
Status: Accepted

Slash commands were listed in four places: the service answered `/model` and
`/models`, the TUI parsed a dozen more, Telegram answered `/start`, `/help` and
`/new`, and each client wrote its own help line. Nothing knew the whole set, so
help drifted and no client could complete a command.

## Decision

- `chat.Registry` on `ConversationService` holds every slash command as a
  `Command`: its `CommandSpec` (name, usage, summary, clients), argument
  completers and how it runs. Commands about conversations and models register
  in `internal/chat/builtins.go`; commands about plugins register in
  `internal/app/commands.go`, beside the code they call. A command lists only
  the clients that can carry it out (`web`, `tui`, `telegram`, `wechat`).
- A **transcript** command (`/model`, `/models`) is answered by the chat stream
  and recorded in the conversation. Every other command runs through
  `POST /api/commands/run` and returns a `CommandResult`: Markdown to show
  (tables for listings, fenced blocks for raw output) and an optional `Action`
  the client performs itself: `open-conversation`, `decide` (an approval, sent
  through the client's own stream), `open-plugins` or `compose-mail`. Text that
  is not such a command comes back `handled: false` and the client sends it as
  chat, so unknown `/words` still reach the model.
- `GET /api/commands?client=NAME` returns a client's specs.
  `POST /api/commands/complete` takes `{client, conversationId, text}`, where
  `text` is the input up to the cursor, and returns suggestions that replace its
  last whitespace-separated token. Free text, multi-line input and finished
  arguments return `[]`. Arguments complete from live state: models, conversations,
  pending approvals, plugin secret fields and fixed choices. Vendor model
  listings get two seconds, so typing never waits on a slow provider.
- Both UIs share one interaction: Tab accepts, ↑/↓ choose, Esc dismisses, and
  Enter accepts only when the suggestion changes a partly typed token, so a
  complete command still sends. Stale answers are dropped.
- Telegram runs `/help`, `/new`, `/approve` and `/deny` through the registry and
  applies the actions it can (it keeps its own conversation pointer for
  `open-conversation`). `/approve` and `/deny` without an ID decide the only
  pending request. Owner-only commands refuse other callers; holders of the
  local token and the configured Telegram user are owners.
- The contract types are generated by `cmd/contracts`.

## Consequences

A command is written once, in Go, and every client that lists it gets help,
completion and execution; the web UI gained `/new`, `/list`, `/open`,
`/approve`, `/deny`, `/email`, `/cloud`, `/test`, `/deliveries` and
`/clear-secret`, and the TUI lost its own command parser. Clients still own
their forms (plugin settings, mail compose); an action opens them.

Telegram's `/` menu comes from the registry too: after each connection the bot
calls `setMyCommands`, scoped to the owner's private chat, with the commands it
lists for `telegram` (names Telegram rejects are left out). A failure leaves
polling running and is retried on the next connection.

The TUI renders assistant replies and command results as Markdown with glamour
(dark or light from the terminal background), so results read the same as in the
web UI. Text is stripped of terminal control bytes before rendering; a reply
stays plain while it streams.
