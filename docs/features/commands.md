# Slash commands

Every slash command is written once, in Go, and every client that lists it gets
help, completion and execution from the same definition.

## Registry

- `chat.Registry` on `ConversationService` holds every command as a `Command`:
  its `CommandSpec` (name, usage, summary, clients), argument completers and how
  it runs. Commands about conversations and models register in
  `internal/chat/builtins.go`; commands about plugins in general register in
  `internal/app/commands.go`; a plugin's own commands live in its package (see
  [Extensions](extensions.md)).
- A command lists only the clients that can carry it out (`web`, `tui`,
  `telegram`, `wechat`, `email`). Owner-only commands refuse other callers;
  holders of the local token and each channel's owner are owners.

## Running a command

- A **transcript** command (`/model`, `/models`, `/compact`) is answered by the
  chat stream and recorded in the conversation.
- Every other command runs through `POST /api/commands/run` and returns a
  `CommandResult`: Markdown to show (tables for listings, fenced blocks for raw
  output) and an optional `Action` the client performs itself:
  `open-conversation`, `decide` (an approval, sent through the client's own
  stream), `open-plugins` or `compose-mail`.
- Text that is not a command comes back `handled: false` and the client sends it
  as chat, so unknown `/words` still reach the model.

## Help and completion

- `GET /api/commands?client=NAME` returns a client's specs.
- `POST /api/commands/complete` takes `{client, conversationId, text}`, where
  `text` is the input up to the cursor, and returns suggestions that replace its
  last whitespace-separated token. Free text, multi-line input and finished
  arguments return `[]`. Arguments complete from live state: models,
  conversations, pending approvals, plugin secret fields and fixed choices.
  Vendor model listings get two seconds, so typing never waits on a slow
  provider.
- Web and the original Bubble Tea TUI share one interaction: Tab accepts,
  ↑/↓ choose, Esc dismisses, and Enter accepts only when the suggestion changes
  a partly typed token, so a complete command still sends. Stale answers are dropped.
- Go-owned contract types are generated by `cmd/contracts` into
  `packages/client/src/contracts.ts` with `bun run generate:contracts`.
  `webapp/src/chat/contracts.ts` re-exports them for existing Web imports.

## Experimental TypeScript terminal

`mob tui` defaults to Bubble Tea (`MOB_TUI=go`). To select the source-only
OpenTUI React 0.6.1 pilot, install dependencies with `bun install --frozen-lockfile`
in the checkout, build with `bun run build:cli`, then run:

```sh
MOB_TUI=ts ./build/mob tui --demo
# For a Go binary outside the checkout's build/ directory:
MOB_TUI=ts MOB_TUI_ENTRY=/absolute/path/to/mob/apps/tui/src/main.tsx mob tui
```

Both variants reuse an existing service or own a new one until the terminal
exits. Use `mob start` first to keep it running after exit. The direct
`bun run tui:pilot` entry still requires an already running service. No silent
fallback occurs if the selector, Bun or source entry is unavailable. This is
not a standalone release; Go/Homebrew packaging remains unchanged.
The pilot requires Bun >=1.3.14 with native FFI; Linux x64 with Bun 1.4.2 and
local tmux have been tested. Real IME input, SSH, macOS and Windows have not.

- Enter sends; Ctrl+J inserts a newline. Drafts survive conversation switching
  in memory, not application restarts. Pasted multiline text is sent whole.
- The pilot retains one shared conversation client per conversation. Switching
  detaches its readers, not the Go turn. On reopening, an uncertain send is
  checked against history by its original request ID before offering recovery;
  newer drafts stay untouched and the original text is shown separately. An
  unconfirmed message is never automatically resent (see [Turns](turns-and-context.md)).
- F2 opens conversations, F3 tool details, F4 approval controls. Ctrl+S requests
  backend Stop; Ctrl+Q closes the terminal. Attached clients leave the service
  turn running; an owning `mob tui` launcher also shuts down its service.
- Slash commands run through the shared client, but the pilot has no autocomplete
  UI. Tab switches search/list focus in F2; Esc returns to chat.
- Plugin settings and mail-compose forms are not implemented in the pilot;
  their command actions explain the Web/original-TUI fallback.

## Clients

- Web and the experimental TypeScript TUI use `@mob/client` for command
  requests, chat fallback and approval continuations. Web completion requests
  also use this client; the same API is available to future terminal completion.
  Keyboard behavior and forms remain in each UI; single-line slash input is
  checked by Go, while multiline input goes to chat without being interpreted
  as a client command. The pilot uses `client: 'tui'`, not a new command registry.
- Clients own their forms (plugin settings, mail compose); an action opens them.
- The original Bubble Tea TUI renders assistant replies and command results as Markdown with
  glamour (dark or light from the terminal background). Text is stripped of
  terminal control bytes before rendering; a reply stays plain while it streams.
- While a conversation is empty, and while it connects, the Bubble Tea TUI shows
  the pasture in place of the transcript: calves chase flocks of butterflies,
  nap and high-five (pixel-art calves, ASCII butterflies), after
  [ascii-sharks](https://github.com/stackedlol/ascii-sharks). The first message
  or command result replaces it, and it stops drawing once hidden. `mob pasture`
  shows it full screen, where the pointer scares butterflies and a click
  scatters them; q quits.
- Messaging channels run commands through the registry too; see
  [Channels](channels.md). After each connection the Telegram bot calls
  `setMyCommands`, scoped to the owner's private chat, with the commands listed
  for `telegram` (names Telegram rejects are left out). A failure leaves polling
  running and is retried on the next connection.
